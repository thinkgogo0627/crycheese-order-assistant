# 크라이치즈버거 AX 해커톤 주제1 — 발주 의사결정 도우미 (통합본)

팀 MVP(화면·API·매장 간 이동 구조)에 별도로 검증한 수요 예측과 발주 로직을 합친 버전입니다.

## 화면 (`/dashboard`)

| 탭 | 내용 |
|---|---|
| 오늘 발주 | 매장·공급사별 발주 추천. 품목마다 **근거 문장**(예상소요 + 안전재고 − 사용가능 재고 → 수량), 최소금액 처리(이월/채움), 발주하지 않는 품목과 이유 |
| 재고 알림 | 오늘 부족 예상, 사용기한 임박, 과잉 재고, 미사용 재고(취급 종료 메뉴의 식자재) |
| 매장 간 이동 | 09:00 출발 이동 추천. 목적(품절 방지/폐기 방지), 회피 손실 vs 운송비, 보류된 이동 |
| 수요 예측 | 7일 예상 판매량(공휴일 표시), 메뉴별 예측, 예측에 쓰인 요일지수·공휴일 계수·행사 배율 |
| 시나리오 비교 | M0 / M0+이동 / M1·M2(통합발주 가정)를 예측 수요 기준으로 비교. 수요 배율·입고 지연 민감도용 |
| 백테스트 검증 | 실제 수요로 다시 돌린 성과(2~9월, 7~9월)와 변형 수요 5개 경로 결과 |

조건: 기준일(7/1~10/1, 기본 10/1), 매장, 안전재고 수준 α(1.2/1.6/2.0), 기간, 수요 배율, 입고 지연, 운송비, 소분 허용.

## 로직

**수요 예측 (`app/forecast.py`)**: 메뉴별 EWMA(α=0.1) × 매장 요일지수(최근 8주, 공휴일 제외) × 공휴일 계수(과거 공휴일 실적) × 행사 배율(기준일 전에 끝난 행사에서 측정). 대상은 확정 수요(`demand_qty − cancel_qty`, 품절로 잘리지 않은 값). BOM으로 식자재 소요량 변환.
6~9월 롤링 백테스트(식자재별 WAPE)에서 7일 평균 34.4%, 동일요일 4주 평균 34.2%, 50:50 혼합 32.4%, LightGBM 30.0~30.8% 대비 **30.0%**로 가장 낮거나 같았고, 설명이 쉬워 채택.

**발주 (`app/engine.py`)**
1. 오늘부터 다음 정기입고 전날까지 예측 소요를 FEFO로 재고(입고 묶음별 사용기한)·입고 예정분에서 차감 → 부족량, 기간 끝 잔량, 기한 경과 예상량.
2. 안전재고 = z_i × (다음 입고까지 합계 예측오차 RMSE, 최근 42개 기준일, 기준일 전 실적만).
   z_i = α × Φ⁻¹(cu/(cu+co)). cu = 이 식자재 1단위가 모자라면 막히는 메뉴 공헌이익, co = 1단위 초과 보유비용(보관 손실 + 짧은 사용기한의 만료 위험). 치즈·번·패티처럼 떨어지면 버거 전체가 멈추는 품목은 z가 크고, 양상추·우유처럼 빨리 상하는 품목은 작음.
3. 발주량 = 올림((부족량 + max(0, 안전재고 − 잔량)) ÷ 포장단위). 냉장은 입고 후 14일 소요, 냉동·상온은 사용기한 안에 쓸 수 있는 양으로 상한.
4. 최소 발주금액 미달: 급한 품목이 없으면 다음 발주일로 이월, 있으면 사용기한 위험이 낮고 보유일수가 짧은 품목을 1단위씩 앞당겨 충족.
5. 매장별 발주서(제공 데이터의 발주 규칙). 통합발주(M1·M2)는 가정 시나리오로만 표시.

**매장 간 이동**: ① 품절 방지(오늘 예상 소요 > 재고, 이득 = 막은 부족량 × 공헌이익) ② 폐기 방지(7일 안에 만료되는데 못 쓸 재고, 또는 쓸 메뉴가 없는 재고, 이득 = 피한 폐기 원가). 경로별 이득 합계 ≥ 운송비일 때만 추천. 예: 8/5 S02 → S01 치킨 패티 27개(치킨버거 7/31 판매 중단 후 남은 재고, 회피 24,588원).

## 검증

```bash
pip install -r requirements.txt pytest httpx
python -m pytest tests -q                      # 17개
```

테스트 항목: 매장별 발주서·최소 발주수량·근거 문장, 최소 발주금액 충족 또는 이월, 공휴일·요일 효과, 단종 메뉴 재고 이동, 이동 시 로트 보존·필요량 초과 금지, 비경제적 이동 미실행, 미래 판매 변경 시 예측·발주 불변, 메뉴 결합 로트 사용·폐기 수지, 입고 후 재고 일치, 이동용 미래 실제 수요 불사용, 한 포장 감량의 최소금액·수량 분해 검증. 이 테스트는 모든 정보 누수의 부재를 보증하지 않는다.

**백테스트 (`tools/backtest`)**: 제공된 합성 이력을 근사하는 재고 시뮬레이터(품절 17 vs 15건, 기한폐기 38.1만 vs 38.0만 원, 평균재고 658.9만 vs 659.0만 원)에서 각 로직을 매일 실행. 아래 기존 결과는 장중 이동에 그날 남은 시간의 실제 수요를 사용하는 참조 모드다. 앱의 아침 이동 함수를 직접 평가한 결과는 아니다.

| 2~9월, 실제 수요 | 총손실(폐기+품절 공헌이익) | 품절 | 폐기 | 평균 재고 |
|---|---|---|---|---|
| 기존 정책 | 2,990,343원 | 16 | 2,132,229원 | 6,717,506원 |
| 팀 초기 로직 | 41,136,337원 | 318 | 954,820원 | 3,081,846원 |
| **통합 엔진 α=1.6 (기본)** | **2,392,063원 (−20%)** | **3** | 2,238,058원 (+5%) | 6,565,535원 |

변형 수요 5개 경로에서도 α=1.6은 5개 모두 기존 정책보다 총손실이 작았음(평균 −11.8%, 경로별 −2.0%~−22.6%). 대신 폐기는 늘어남(평균 +20%). α=1.2는 폐기·재고를 줄이는 대신 총손실 개선폭이 작음.

**폐기 보완 분석 (2026-10-31)**: [로트 원인·선택적 감량/이동 비교](tools/waste_refinement/README.md)와 [집계 결과](tools/waste_refinement/aggregate_results.json). S02 양상추·코울슬로·식빵의 폐기 발주 47로트에서 최소금액 증량은 없었고 안전재고 보충·포장 올림이 컸다. 이동 비용0원, 장중 미래 수요 대신 당시 예측을 사용한 비교에서 예측 폐기 감소 주문만 1포장 줄이는 탐색안은 기한폐기494,307→389,243원, 미판매19.568→15.315개였다. 전 매장·메뉴·날짜별 미판매 증가가 없었지만 예측 부족 비악화 제약을 붙이면 실행0건이므로 자동 정책으로 채택하지 않았다. 양상추 이동 효과는3월3회에 집중, 코울슬로 이동은 미판매 증가, 식빵 이동은 전체 기한폐기 증가였다. 원래 α=1.6 발주를 유지하고 후속 검증 후보로 제공한다.

**재고 알림**: 임박 로트 전체량과 기한 내 예상 사용·최종 예상 폐기를 분리한다. 메뉴별 BOM을 함께 제한하고 기확정 입고를 반영한다. 신규 발주·이동 전의 전망이며 품질폐기는 제외한다. `lots[]`로 일별 사용·폐기·잔량까지 확인할 수 있다. 현재 재고 표는 전일 마감/오늘 입고/입고 후 장부를 구분한다.

## 실행·배포

```bash
pip install -r requirements.txt
python scripts/import_data.py "크라이치즈버거_AX해커톤_주제1_데이터.zip"
uvicorn app.main:app --reload       # http://localhost:8000/dashboard
```

- 서버 시작 시 모든 기준일 예측을 미리 계산(약 1초). `/api/plan` 응답 0.2~0.4초.
- `CRY_DATA_DIR`로 비공개 CSV 폴더 지정. Railway 등에는 비공개 볼륨으로 데이터 주입. 데이터 없으면 `/api/plan` 503.
- `frontend/`(React)의 재고 알림에 로트별 예상 사용·폐기와 입고 전후 재고를 연결했으며 TypeScript/Vite 빌드를 검증했다. 정적 `/dashboard`에도 같은 수치를 표시한다. lint에는 기존 Fast Refresh·배열 key 경고가 남는다.

## 가정과 한계

- 기준일 07시 입고 후·당일 실사 및 이동 전 장부재고 기준, 전날까지의 판매만 사용. 당일 실사조정은 미반영. 9/30 발주 → 10/1 입고분(입고 파일에 없음)은 입고 예정으로 반영.
- 10/3 개천절, 10/5 대체공휴일, 10/9 한글날은 데이터 밖이라 직접 추가한 가정.
- 취급 기간이 9/30에 끝나는 메뉴는 데이터 종료일로 보고 계속 취급으로 해석.
- 행사 배율은 S02 7월 세트 할인 1건에서 측정(1.34배). 10월 예정 행사 정보는 없음.
- 매장 간 거리·운송비는 제공되지 않음. 이번 비교와 API/화면 기본값은 사용자 조건에 따라 이동 비용0원이며, 09:00 출발·30분 도착은 별도 가정이다.
- 통합발주(M1·M2)는 공급사가 매장 합산·소분을 허용한다는 가정이며 제공 데이터의 발주 규칙과 다름.
- 시나리오 비교 탭은 예측 수요 기준이며 실적이 아님. 실제 수요 성과는 백테스트 탭.
- 예측에 쓰는 `demand_qty`(품절이 없었다면 들어왔을 주문)는 실제 매장에서는 직접 관측되지 않음.
- 일부 공헌이익·안전재고는 전체 단가 이력 평균의 영향을 받는다. 미래 판매 불사용 검사와 별개로 남아 있는 시점 한계다.
- 모든 금액은 가상 가격이며 합성 데이터 결과를 실제 매장 성과로 해석하지 않음.
